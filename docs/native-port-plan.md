# 탭투시티 네이티브(Flutter) 이식 계획

- 작성: 2026-10-12
- 결정: Flutter로 시즌 1 전체를 옮긴 뒤, 같은 앱에서 시즌 2를 이어서 개발한다.
- 위치: 이 저장소의 `native/` 폴더 (웹 버전은 지금처럼 루트에서 계속 서비스)

## 1. 기본 방향

| 항목 | 결정 |
|---|---|
| 엔진 | Flutter. 지도는 `CustomPainter`로 직접 그리고, 메뉴·시트·대화창은 Flutter 위젯으로 만든다. Flame은 계속 도는 게임 루프가 발열 원인이 될 수 있어 쓰지 않는다 (연출이 필요한 곳에만 부분 도입 검토). |
| 앱 ID | `kr.co.itso.taptocity` 그대로. 스토어에 올린 웹 감싸기 앱을 **업데이트로 교체**한다. |
| 저장 형식 | 웹 저장 JSON(`taptocity-shelter-v1`)과 **같은 필드 이름**을 쓴다. 모르는 필드도 지우지 않고 그대로 보관한다. |
| 진행 이전 | ① 클라우드 저장(같은 Firebase 프로젝트 `taptocity-bd5d1`, `saves/{uid}`) ② 저장 코드(`TTC1.…`) 두 경로 모두 지원. 웹에서 하던 사람은 그대로 이어서 한다. |
| 그림 | `assets/illustrated/`의 아틀라스를 그대로 쓴다. 자르기 좌표는 `design.js` 등에서 옮겨 Dart 상수로 둔다. |
| 소리 | 웹은 WebAudio로 실시간 합성. 네이티브는 같은 소리를 **미리 파일(ogg)로 구워** 재생한다 (실시간 합성은 발열 원인). |
| 빌드 | 작업 공간에서는 Flutter 도구 다운로드가 막혀 있어, **GitHub Actions에서** 분석·테스트·안드로이드 APK·웹 미리보기를 빌드한다. iOS는 기존처럼 클라우드 Mac. |

## 2. 발열 개선 원칙 (웹 버전 분석 결과 반영)

웹 버전은 화면을 계속 다시 그리는 구조라 휴대폰이 뜨거워진다. 주요 원인과 대응:

| 웹 버전 원인 | 네이티브 대응 |
|---|---|
| `requestAnimationFrame`이 멈추지 않고 돌며 지도 전체를 다시 그림 | 게임 시간은 **1초 타이머**로만 진행. 지도는 **바뀔 때만** 다시 그림. 애니메이션은 연출이 있는 동안만 켰다가 끝나면 끔 |
| 그때마다 그라디언트 글로우·비네트·눈송이 70개 생성 | 밤·글로우·비네트는 **미리 그려 둔 그림**을 겹쳐서 사용 |
| `frontierNearest()`가 매초 1,600칸 전체를 훑음 | 밝힌 경계 칸 목록을 **바뀔 때만 갱신** |
| 0.25초마다 HUD DOM 갱신, 5초마다 전체 저장 | 값이 바뀐 위젯만 다시 그림. 저장은 **변경이 있을 때 디바운스**(최소 10초) + 앱이 백그라운드로 갈 때 |
| 무한 CSS 애니메이션 30여 개, `backdrop-filter` | 반복 애니메이션은 화면에 보일 때만. 블러 제거 |
| 120ms 음악 스케줄러, 오실레이터 상시 생성 | 미리 구운 음원 재생 |
| 앱이 백그라운드여도 루프가 돎 | 백그라운드에서 **완전히 멈추고**, 돌아오면 오프라인 진행으로 계산 |

목표: 일반 플레이 중 프레임을 거의 쓰지 않는 상태(정지 화면 0fps), 30분 연속 플레이 시 웹 대비 기기 온도·배터리 소모가 확실히 낮을 것.

## 4. 끊긴 노선 난이도 (6단계에서 결정)

현재 값 (웹 3476–3620): 판정 원 반지름 46에서 ±4면 2피해, ±10이면 1피해. 원 줄어드는 시간 1,250/1,120/990ms(우두머리 950ms). 실패 시 체력 -2(우두머리 -3). 2인 팀 체력 16.

개선안 후보 (6단계에서 직접 해 보고 정함):
- 판정 범위를 화면 크기에 맞춰 넓히고(터치 지연 보정 포함), 원 시간 하한을 1,100ms로
- 연속 성공 시 다음 원을 느리게, 연속 실패 시 한 번 쉬어 가는 "숨 고르기"
- 휴식 카드 회복량 상향, 우두머리 직전 역에서 체력 일부 회복

## 5. 자동 빌드 (GitHub Actions `native.yml`)

`native/` 폴더가 바뀌어 올라가면:
1. 코드 검사(`flutter analyze`)와 테스트(`flutter test`) — 웹과 같은 공식으로 계산되는지 확인
2. 안드로이드 APK 빌드 → 실행 결과 화면에서 내려받아 휴대폰에 설치
3. 웹 미리보기 빌드 → https://gogeangs.github.io/taptocity/native-play/ 에서 바로 확인 (발열·성능 판단은 APK로)
