# 탭투시티 네이티브 출시 준비 (8단계)

- 작성: 2026-10-13
- 대상: 네이티브 앱 2.0.0 (빌드 100) — 지금 스토어에 있는 웹 감싸기 앱(1.0.0)을 **같은 앱 ID로 업데이트**
- 원칙: 스토어 업로드·제출은 **대표님 확인 후에만** 한다. 자동 빌드는 파일만 만든다.

## 1. 끝난 것 (앱 안)

| 항목 | 내용 |
|---|---|
| 클라우드 저장 | 같은 Firebase 프로젝트 `taptocity-bd5d1`의 `saves/{uid}`. SDK 대신 REST(익명 로그인·토큰 갱신·Firestore). 켤 때 클라우드가 더 최근이면 묻고 불러오기, 45초마다·앱이 뒤로 갈 때 올리기, 지금 저장, 클라우드 데이터 삭제. 웹과 문서 모양 같음 |
| 키 확인 | 공개 API 키에 앱 제한이 없어 앱(웹 주소 없음)에서도 통함 — 자동 빌드에서 매번 확인 (`클라우드 키 확인` 단계) |
| 피드백 | 설정 → 피드백 보내기. 웹과 같은 `feedback/{id}` 문서·규칙. 연결이 없으면 기기에 모았다가 다음에 보냄 |
| 앱 오류 보고 | 잡히지 않은 오류를 `feedback`에 `cat: crash`로 (같은 오류 한 번, 하루 5건까지, 이름·연락처 없음). 관리자 페이지에 '앱 오류' 분류 추가 |
| 예전 진행 옮기기 | 아래 2절 |
| 플랫폼 설정 | `tool/platform_setup.py`: 앱 이름 탭투시티, 세로 고정, 인터넷 권한, `taptocity://import` 링크, 아이콘(웹·iOS 아이콘 그대로), iPhone 전용, 상태 표시줄 숨김, 암호화 신고 없음 |
| Android 번들 | 저장소 시크릿에 업로드 키가 있으면 `taptocity-aab`(스토어용 .aab)도 만든다. 없으면 미리보기 APK만 |
| iOS | `Native iOS` 워크플로: 클라우드 Mac에서 컴파일 확인. TestFlight 업로드는 **수동 실행에서 upload를 켤 때만** (기존 iOS 앱과 같은 API 키·클라우드 서명) |

## 2. 예전 버전 진행이 새 앱으로 넘어오는 길

| 하던 곳 | 새 앱에서 | 비고 |
|---|---|---|
| iPhone 앱(1.0.0, 웹 감싸기) | 첫 실행 때 숨은 웹뷰로 예전 앱 저장소를 읽어 "이어서 할까요?" | 같은 번들·같은 웹사이트 저장소라 가능. **실기기 확인 필요** |
| Android 앱(1.0.0, TWA) | 설정 → '예전 버전에서 진행 가져오기' → 크롬으로 `transfer.html`이 열리고 '새 앱으로 보내기' → `taptocity://import`로 돌아와 불러오기 | 예전 앱은 크롬 저장소를 써서 직접 못 읽음. 기본 브라우저가 크롬이 아니면 크롬에서 주소를 열어야 함 |
| 웹 브라우저 | 웹 미리보기(같은 주소)는 첫 실행 때 바로 읽음. 휴대폰 앱으로는 `transfer.html` 또는 저장 코드 | |
| 어디서든 | 설정 → 저장 코드(TTC1.) 복사·붙여 넣기 | 웹과 같은 형식 |
| 웹에서 구글 계정 연결한 사람 | 저장 코드 또는 `transfer.html` | 앱의 구글 로그인은 아래 3-③ 결정 후 |

## 3. 대표님 결정·작업이 필요한 것

① **광고·인앱 결제** — 지금 Play 출시 노트에 '광고 없음'. 넣을지, 넣는다면 무엇을(보상형 광고·후원 상품·시즌 2 유료 등).

② **오류 보고 방식** — 지금은 자체 경량 보고(피드백 컬렉션). Firebase Crashlytics(오류 상세·통계)를 쓰려면 Firebase 콘솔에 Android·iOS 앱을 등록해 설정 파일을 받아야 함.

③ **앱의 구글 로그인** — 웹은 익명 → 구글 연결. 앱에서 구글 로그인을 하려면 Firebase 콘솔에 Android 앱(패키지 `kr.co.itso.taptocity` + 업로드·앱 서명 키 SHA-1)과 iOS 앱을 등록해야 함. 지금은 익명 자동 백업 + 저장 코드 + 옮기기 페이지.

④ **Android 업로드 키 등록** — PWABuilder로 받은 `signing.keystore`를 GitHub 저장소 시크릿에:
- `TTC_KEYSTORE_B64` = keystore 파일을 base64로 바꾼 글 (`base64 -w0 signing.keystore`)
- `TTC_KEYSTORE_PASS`, `TTC_KEY_ALIAS`, `TTC_KEY_PASS` = `signing-key-info.txt`의 값
등록하면 다음 빌드부터 스토어용 .aab가 만들어짐. (키를 잃어버렸다면 Play Console → 앱 무결성 → 업로드 키 재설정 요청)

⑤ **개인정보 처리방침 갱신** — 앱 오류 자동 보고를 넣었으므로 출시 전에 아래 문단 추가 (3항 '피드백' 아래):
> **앱 오류 보고** — 새 앱(2.0.0부터)은 예기치 않은 오류가 나면 오류 내용과 진행 요약(쉘터 레벨·동네·진행 단계)·기기 종류·화면 크기를 같은 클라우드로 보냅니다. 같은 오류는 한 번만, 하루 5건까지 보내며 이름·연락처는 담지 않습니다. 게임을 고치는 데만 씁니다.

Play 데이터 보안·App Store 앱 개인정보의 '진단' 항목은 이미 신고돼 있어 바꿀 것 없음.

## 4. 출시 순서 (확인 후)

1. 휴대폰에서 미리보기 APK로 소리·진행 옮기기·클라우드 저장 확인
2. 업로드 키 등록 → .aab 생성 → Play Console 내부 테스트 → 프로덕션 업데이트
3. `Native iOS` 수동 실행(upload 켬) → TestFlight 확인 → App Store 2.0.0 심사 제출
4. 개인정보 처리방침 갱신, 스토어 문구(“광고 없음” 등) 확인

출시 노트 초안 (2.0.0):
> 탭투시티가 새 엔진으로 다시 태어났어요. 휴대폰이 덜 뜨겁고 배터리가 오래가요. 소리·음악을 새로 담았고, 동네마다 풍경이 달라졌어요. 예전 진행은 설정 → '예전 버전에서 진행 가져오기'로 옮길 수 있어요.
